# 招聘系统通过 Playwright 同步 NocoBase 设计

日期：2026-09-16  
状态：设计已确认，等待用户复核后制定实施计划

## 1. 目标与范围

在 NocoBase 暂无可用 API 的情况下，通过 Playwright 模拟网页操作，将招聘管理系统的数据长期同步到 NocoBase。

第一阶段只同步以下两个模块：

- 简历收集（`resume_documents`）
- 人才库（`candidates`，包括教育经历、工作经历和项目经历）

同步包括现有历史数据以及以后发生的新增、修改和删除。同步方向仅为“招聘系统 → NocoBase”，不把 NocoBase 中的人工修改反向写回招聘系统。招聘系统的本地数据库是当前唯一数据源；NocoBase 是长期同步数据库。

不在第一阶段同步应聘登记、面试、员工、院校等其他模块。

## 2. 已确认的约束

- NocoBase 默认地址为 `http://cloud.njncc.com:443/`，不得写死在业务代码中。
- 登录方式为普通用户名和密码，无短信或动态验证码。
- NocoBase 已存在“简历收集”和“招聘人才库”数据表。
- Playwright 使用电脑自带的 Microsoft Edge，默认后台无界面运行。
- 简历附件需要上传到 NocoBase，而不是仅保存本地链接。
- 本地删除后需要删除 NocoBase 对应记录，同时保留本地同步审计日志。
- 首次执行历史全量同步，之后持续增量同步。
- 增量任务立即进入队列，由后台逐条处理，失败自动重试。

## 3. 架构

采用独立同步进程，避免 Playwright 卡顿、浏览器崩溃或 NocoBase 网络异常影响招聘系统 HTTP 服务。

```text
招聘系统新增 / 修改 / 删除
            │
            ▼
本地 SQLite 持久化同步队列
            │
            ▼
独立 NocoBase 同步进程
            │
            ▼
后台 Playwright + Microsoft Edge
            │
            ▼
登录 NocoBase → 定位数据表 → 按档案编号查找
            │
            ├─ 不存在：新增
            ├─ 已存在：更新
            └─ 删除任务：删除并确认
```

`start.bat` 和 `start.ps1` 启动招聘系统时同时启动同步进程。同步进程只允许一个实例取得工作锁；重复启动时，后启动的实例退出，避免同一任务被并发执行。

## 4. 模块边界

新增模块建议放在 `features/nocobase_sync/`，避免继续扩大 `server.py`：

- `config.py`：读取网址、用户名和加密密码。
- `queue.py`：创建、合并、领取、完成和重试同步任务。
- `mapping.py`：把本地记录转换为 NocoBase 字段模型。
- `browser.py`：登录、导航、稳定选择器和浏览器生命周期。
- `resume_documents.py`：简历收集的查找、新增、更新、删除和附件上传。
- `candidates.py`：人才库及三个经历子表的查找、新增、更新和删除。
- `worker.py`：后台循环、任务租约、重试和诊断日志。
- `service.py`：供服务器调用的入队、状态查询和历史同步接口。

业务模块只负责在本地事务成功提交后入队，不直接调用 Playwright。

## 5. 配置和凭据安全

新增 `配置NocoBase.bat`，调用专用配置程序：

- 默认网址为 `http://cloud.njncc.com:443/`。
- 支持随时修改 NocoBase 网址，不需要改代码。
- 支持录入或更换用户名和密码。
- 密码输入时不回显。
- 密码使用 Windows 当前用户的 DPAPI 加密后保存；不以明文写入源码、SQLite、日志或生成的 Playwright 脚本。
- 用户名和规范化后的网址可以明文保存在本机配置文件中。
- “测试连接”只验证网址和登录，不新增、修改或删除业务数据。

同步日志不得记录密码、Cookie、附件内容、简历原文、人才姓名、电话、邮箱、身份证号或完整网页内容。

## 6. 队列数据模型

新增持久化表 `nocobase_sync_jobs`：

- `id`：任务编号。
- `entity`：`resume_documents` 或 `candidates`。
- `local_id`：本地记录编号；删除后可为空，但任务保留原值。
- `archive_no`：档案编号，是 NocoBase 查找和幂等更新的唯一业务键。
- `operation`：`upsert` 或 `delete`。
- `revision`：本地记录版本号或更新时间快照。
- `status`：等待、处理中、成功、失败、暂停。
- `attempts`：已执行次数。
- `next_attempt_at`：下次重试时间。
- `lease_owner`、`lease_until`：防止多个同步进程重复领取任务。
- `error_stage`、`error_type`、`diagnostic_id`：隐私安全的错误信息。
- `created_at`、`updated_at`、`completed_at`：任务时间。

新增 `nocobase_sync_audit`，保存每次操作的实体、档案编号、操作、结果、诊断编号和时间，不保存人才字段或附件内容。

## 7. 入队、合并和版本规则

- 本地新增或修改成功后立即入队 `upsert`。
- 本地删除成功后立即入队 `delete`，删除任务需保存档案编号快照。
- 同一实体、同一本地记录短时间连续修改时，等待中的任务合并为最新版本。
- 正在执行旧版本时发生新修改，创建新版本任务；旧任务完成后不能把新任务标记为完成。
- 删除任务优先于等待中的新增或修改，并取消同一记录尚未执行的 `upsert`。
- 工作进程执行 `upsert` 时读取本地最新数据，而不是使用队列中的旧字段副本。
- 任务没有有效档案编号时暂停并显示明确错误，禁止用姓名或列表位置猜测记录。

## 8. NocoBase 定位与幂等策略

两个数据表均以档案编号为唯一定位依据：

1. 打开对应数据表。
2. 打开筛选器。
3. 添加“档案编号 = 实际档案编号”条件。
4. 提交筛选。
5. 结果为零条时新增；结果为一条时编辑或删除；结果多于一条时停止任务并记录重复数据错误。

禁止依赖列表第一行、“刚新增的记录”、固定页码或录制代码中的测试常量。禁止直接使用未限定范围的“编辑”“删除”按钮。

优先使用角色、字段标签和对话框范围内的稳定选择器。录制代码中的 `nth()`、动态列表 ID 和超长 CSS 路径只作为探索证据，实施时需要替换为限定在当前弹窗、当前子表和当前记录行内的选择器。

## 9. 简历收集映射

同步本地简历收集中的：

- 档案编号
- 处理状态
- 招聘类型
- 招聘渠道
- 其他渠道详情
- 应聘岗位
- 其他岗位名称
- 简历名称
- 创建人
- 上传时间
- 简历附件

附件通过真实文件路径上传。任务执行前验证附件存在、文件类型可接受、大小符合 NocoBase 限制；失败时只记录阶段和诊断编号，不记录文件名或文件内容。

## 10. 人才库映射

同步人才基础字段以及当前系统保存的完整人才信息，包括：

- 姓名、性别、出生年月、年龄、政治面貌
- 档案编号、学历、毕业院校、专业
- 联系方式、邮箱、籍贯/居住地
- 招聘类型、招聘渠道、其他渠道详情
- 投递岗位、其他岗位名称
- 校园招聘专属字段（如毕业时间、应届状态）
- 简历附件
- 教育经历子表
- 工作经历子表
- 社会招聘项目经历子表

具体字段来源以 `features/candidates/schema.json` 和现有经历服务为准，映射使用明确白名单，不把内部数据库字段、删除标记、队列字段或调试字段写入 NocoBase。

经历子表更新采用“按本地最新完整内容重建 NocoBase 子表”的第一阶段策略，以保证顺序和删除一致：

- 教育经历、工作经历、项目经历按本地保存顺序写入。
- 日期统一为系统已规范化的年月格式。
- 招聘类型为校园招聘时不写项目经历。
- 招聘类型为社会招聘时不写校园招聘专属的应届字段。

## 11. 日期和动态表单处理

录制确认 NocoBase 的“工作经历开始时间”以及选择“社会招聘”后动态出现项目经历区域会与 Playwright Codegen 发生冲突。正式同步不重放录制动作，而采用确定性实现：

- 日期字段按对应子表行和字段标签定位，直接填入规范化年月，不通过反复点击“上一年”。
- 填写后按 Enter 或 Tab，并等待日期弹层消失。
- 选择招聘类型后等待对应动态区域出现或消失，再继续填写。
- 等待以可观察元素状态为条件，不使用任意固定长时间睡眠。

## 12. 后台浏览器生命周期

- 使用 `playwright.chromium.launch(channel="msedge", headless=True)`。
- 同步进程启动后创建一个浏览器；会话失效时重新登录。
- 每条任务使用受控页面，完成后清理弹窗、筛选和临时上传状态。
- 浏览器崩溃、页面超时或进程失联时关闭当前实例并重建。
- 正常情况下不显示 Edge 窗口；“测试连接/诊断模式”允许显式启动可见窗口。
- 不保存含个人信息的页面截图或 HTML 快照。

## 13. 重试和暂停规则

默认重试间隔：

1. 第一次失败后 1 分钟。
2. 第二次失败后 5 分钟。
3. 第三次失败后 15 分钟。
4. 第四次失败后 30 分钟。
5. 此后每小时重试。

登录失败、网络超时、浏览器崩溃可以自动重试。以下情况自动暂停任务，等待管理员处理：

- 筛选出多条相同档案编号记录。
- NocoBase 字段或按钮找不到，表明页面结构已经变化。
- 本地档案编号为空或无效。
- 附件不存在或超出限制。
- NocoBase 校验明确拒绝字段值。

一个任务失败不得阻塞其他任务。错误提示包含阶段和诊断编号，不包含个人数据。

## 14. 管理页面

招聘系统增加“NocoBase 同步状态”入口，展示：

- 等待、处理中、成功、失败和暂停数量
- 最近一次成功同步时间
- 历史全量同步进度
- 失败阶段、简化原因和诊断编号
- 单条重新同步
- 全部失败任务重新同步
- 暂停或继续历史同步
- 测试连接

管理页面不显示密码，也不返回浏览器 Cookie 或完整异常栈。

## 15. 首次历史同步

首次部署后不自动向真实 NocoBase 批量写入，采用明确的安全流程：

1. 配置网址、用户名和密码。
2. 执行测试连接，只验证登录。
3. 显示简历收集、人才库、附件的待同步数量。
4. 同步一条专用测试简历和一条专用测试人才。
5. 用户在 NocoBase 中检查字段、经历和附件。
6. 用户点击“开始历史同步”。
7. 全部历史记录按队列逐条执行，可暂停、继续。
8. 完成后显示成功、失败、暂停和跳过数量。

测试记录使用明显的测试档案编号和虚构个人信息。正式同步前删除测试记录，并通过同步删除验证两边一致。

## 16. 测试策略

自动化测试不得向真实 NocoBase 写数据。

- 队列单元测试：入队、任务合并、版本保护、删除优先、租约恢复和重试时间。
- 配置测试：网址规范化、缺失配置提示、密码加密保存和日志脱敏。
- 映射测试：简历字段、人才字段、校园/社会招聘条件字段和三个经历子表。
- Playwright 组件测试：使用本地模拟 NocoBase 页面验证登录、筛选、新增、编辑、删除、附件上传和动态表单等待。
- 故障测试：登录失败、网络中断、超时、重复档案编号、字段缺失、附件不存在和浏览器崩溃。
- 生命周期测试：服务器和同步进程启动、单实例锁、退出和重启后继续任务。
- 回归测试：现有招聘系统全套测试必须继续通过。

真实环境验收仅使用两条专用测试记录。在用户确认测试结果并明确启动历史同步前，不批量写入真实 NocoBase。

## 17. 验收标准

- 简历收集和人才库的新增、修改、删除能自动进入持久化队列。
- 同步进程后台逐条处理，不阻塞招聘系统保存和查询。
- 同一档案编号不会因为重试产生重复记录。
- 简历附件能在 NocoBase 中直接打开。
- 人才教育、工作、项目经历与本地最新数据一致。
- 招聘类型专属字段符合校园招聘和社会招聘规则。
- 服务或电脑重启后未完成任务继续执行。
- NocoBase 暂时不可用时本地数据不丢失，恢复后自动重试。
- 页面结构变化时任务安全停止，不误编辑或删除其他记录。
- NocoBase 地址可以通过配置工具快速更换。
- 密码、Cookie、附件内容和个人信息不进入日志。

## 18. 后续扩展

后续获得 NocoBase API 后，只替换浏览器适配层，保留队列、映射、重试、审计和管理页面。后续需要同步应聘登记、面试或员工模块时，为相应实体增加独立映射和适配器，不修改现有两个模块的同步逻辑。
