# 南化建校园招聘管理系统

支持 Windows 局域网部署的前后端一体服务。前端为原生 HTML/CSS/JavaScript，后端为 Python HTTP API，使用 SQLite 持久化。Excel 与二维码功能使用项目内依赖，安装完成后运行无需连接外网。

## 启动

安装 Python 3.10 或以上版本并加入 PATH。本机已安装依赖；在新电脑首次部署时，在项目目录运行 `python -m pip install --target .runtime -r requirements.txt`，也可将已有 `.runtime` 文件夹随项目复制到兼容的 Python 环境。然后双击 `start.bat`，或在项目目录运行：

```powershell
python server.py --host 0.0.0.0 --port 8116
```

本机管理端：http://localhost:8116 。学生登记页：http://localhost:8116/apply 。保持启动窗口运行，关闭窗口会停止服务。

管理员账号 `admin`，首次启动生成随机密码，保存在 `data/initial-password.txt`。登录后右上角可修改密码，修改后初始密码文件自动移除，该账号的所有登录会话失效。也可在首次启动前设置 `RECRUIT_ADMIN_PASSWORD` 环境变量。已有数据库时不会覆盖密码。

## 局域网访问

启动时会自动识别系统当前默认网络出口对应的局域网 IPv4，并打印访问地址；无需在 `start.bat` 中预设 IP。其他电脑或手机连接同一网络，访问 `http://服务器IPv4地址:8116`；将后缀为 `/apply` 的地址发给学生。多网卡时优先采用默认出口地址，并排除回环、自动专用和无效地址；如确需指定固定域名或地址，仍可在启动前设置 `RECRUIT_PUBLIC_URL` 环境变量覆盖。

若无法访问，检查 Windows 防火墙是否允许 Python 或 TCP 8116 入站。以下命令需管理员 PowerShell，可仅对专用网络中的本地子网开放：

```powershell
New-NetFirewallRule -DisplayName "Campus Recruitment LAN 8116" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8116 -Profile Private -RemoteAddress LocalSubnet
```

服务电脑应保持开机，建议在路由器中固定其局域网地址。端口冲突时使用 `--port 8081` 并调整访问地址和防火墙端口。当前为局域网 HTTP 服务；若需跨公网使用，应另行配置 HTTPS 反向代理、访问控制和生产级服务进程。默认配置不适合直接暴露到公网。

## 六个业务模块

| 模块 | 内容 |
| --- | --- |
| 院校基础库 | 学校名称、地区、业务开发领导、省、市、办学层次与形式、985/211/双一流标记、就业网账号/密码/网址、排名、自动生成的所在省市 |
| 校园招聘人才库 | 创建日期、姓名、出生日期、年龄、院校、性别、学历、专业、毕业年月、电话、邮箱、政治面貌、籍贯/居住地、招聘渠道、简历、毕业届别、投递岗位 |
| 校园招聘应聘登记 | 基本信息、初筛、一面安排、教育与语言能力、附件与签名、招聘信息、院校标记 |
| 校园招聘面试情况表 | 人员资料、一面意愿、流程状态、分钟级面试时间、附件、个人情况、一面二面说明、面试结果 |
| 新员工信息登记表 | 关联人才、员工编号、部门、岗位、报到状态 |
| 应聘人员问题库 | 咨询问题、分类、答复、负责人；可关联具体人才 |

每个模块支持新增、查看、修改、删除、关键词查询、分页、刷新、Excel导入/导出和二维码打印。导出当前搜索范围的所有记录（不限当前页），生成真正的 `.xlsx` 文件，附带标题行、筛选和冻结表头。就业网密码不参与搜索，也不导出。就业网密码在编辑表单中默认隐藏，可点击显示，由已登录管理员查看和修改。数据库初始为空，不混入虚构人员。

### Excel 导入

点击“导入 Excel”，可下载本模块导入模板或选择已有 `.xlsx` / `.xls` 文件。自动识别前20行中的表头，可切换工作表、手动调整列对应字段；预览显示前20条记录，错误显示Excel原始行号。文件最大8MB，每次最多1000条、150列。XLSX公式字段需先粘贴为值；XLS读取文件保存的计算结果，不运行公式或宏。预览有效期15分钟，刷新列表不会写入预览数据。

确认导入仅新增，不按编号覆盖原数据；整批校验成功才写入，出现重复、无效字段或关联失效时整批回滚。人才手机号和入职人员仍有唯一约束；其他模块重复内容未设置业务唯一规则，应自行避免重复导入。关联人员可填写档案编号、唯一姓名或手机号，院校可填写档案编号或唯一名称。重名时请用编号/手机号。建议先导入院校，再导入人才，最后导入业务记录。缺少招聘阶段列时沿用新增表单默认状态。导出表中的关联编号可直接识别；导出记录再次导入会被视为新增。

### 二维码与打印

六个模块的列表均支持“删除所选”：勾选单条、多条或本页全选，可跨页选择，每次最多1000条。确认弹窗列出实际勾选记录（包括搜索前勾选的记录）。确认后整批删除；有任何记录被关联引用或已不存在时整批回滚，不会部分删除。成功删除人才档案时同步清理对应简历附件。刷新或切换模块会清空勾选。

列表首列可选择单条、多条或本页全部记录，支持跨页选择；顶部“打印二维码”批量生成，每次最多100条。每条记录旁也有单独的“二维码”按钮。预览后可打印或在浏览器打印窗口保存为 PDF，采用A4双列卡片布局。刷新/切换模块清空勾选。

二维码内容为该记录的管理端链接，不包含档案详情或就业网密码。扫码设备需连接同一局域网并登录，登录后自动打开对应档案。若在 localhost 访问，系统会自动使用当前默认网络出口对应的局域网 IP 生成二维码；固定域名环境可设置 `RECRUIT_PUBLIC_URL` 覆盖。服务器IP或端口改变后，应重新打印二维码。

院校“所在地区”可选华中、华东、华南、华北、西北、东北、西南；办学层次为专科/本科，办学形式为公办/民办。985、211、双一流分别选择是/否，未填写时不自动判断。“所在省市”根据省和市自动合成，保存时由后端重新计算。院校排名可留空，填写时须为正整数。就业网网址填写完整的 HTTP/HTTPS 地址。

所在省、市采用联动下拉选择，覆盖34个省级选项。直辖市的城市选项为该直辖市，香港、澳门对应同名城市；其他地区提供地级市、自治州及省直辖县级行政单位。切换省份会清空原城市，后端拒绝省市不匹配的数据。省份简称（如江苏）可自动规范为江苏省；无法匹配的旧文本会在编辑表单中提示重新选择，不自动修改数据库。

省市数据离线保存在 `web/china-locations.json`，使用时无需访问外网。来源为 [Administrative-divisions-of-China](https://github.com/modood/Administrative-divisions-of-China) 的 `dist/pca.json` 和 `dist/HK-MO-TW.json`（2026-09-07 下载的数据快照，上游大陆数据标注为2023年，港澳台为人工整理）；不声明自动跟踪最新行政区划。原始数据和许可一并保留，更新后运行 `python scripts/build_locations.py` 重新生成，再重启服务。

旧版本院校表首次升级前，服务会在 data 下自动生成 before-school-update 时间戳备份。原有记录编号及人才关联保留，旧版特有字段仍保留在数据库中；“高职专科”转换为“专科”，旧的非本科/专科层次保存在 legacy_level 字段，新的办学层次留待补充。旧版“所在省市”原文先保留在“所在省”字段中，需按实际情况拆分填写省、市，不自动猜测。

学生自主登记同时生成一条人才档案和应聘登记，两条记录在同一事务中写入。手机号在人才库中唯一；同一人才只能建立一份入职登记。院校和人员采用外键约束，被业务记录引用的档案无法直接删除。人才招聘阶段由管理员在人才库维护，各业务表状态独立，避免面试多轮记录相互覆盖。手工新增人才不会自动创建应聘记录，需在应聘登记模块添加。

“应聘人员问题库”暂按学生咨询与答复口径实现，也包含“专业能力”分类与参考答案字段，可根据实际面试题库要求调整。

## 数据与维护

数据位于 `data/recruitment.db`。备份时先关闭服务，再复制整个 `data` 文件夹；恢复时关闭服务，将备份文件夹放回原位置。不要在服务运行时只复制 db 文件（WAL 模式可能还有未合并写入）。备份含个人资料与密码哈希，应限制存储目录访问权限。

支持管理员及成员账号：管理员通过头像菜单的“查看成员”创建成员，成员可新增、查看、编辑、删除全部业务数据，使用导入导出及二维码功能，并修改自己的密码；登录用户可查看成员账号列表，只有管理员可创建成员；头像菜单支持切换账号和退出登录，切换时先注销当前会话并要求输入目标账号密码。账号持久化保存在 SQLite，密码 PBKDF2 加盐存储、8 小时会话、HttpOnly Cookie、登录失败限速、同源提交检查、服务端字段校验；Excel导出将用户文字保存为文本而非公式。学生页面无法读取管理档案。暂未包含操作审计及自动备份；这些可在本版本基础上扩展。

### 人才库字段与简历

人才库另设“投递时间”，可选择日期、时分秒，允许留空，独立于不可修改的创建日期；旧记录不推测投递时间。“投递岗位”为选填，管理端、学生登记和Excel导入均可留空；学生未填岗位时仍生成应聘登记，岗位原样留空。Excel导入导出保留投递时间到秒。

创建日期由服务器在首次提交时生成，显示到秒，编辑和Excel导入均不能指定或修改。年龄在查看时按当前日期和出生日期计算周岁；出生日期不得晚于今天。每条教育经历分别填写入学时间和毕业时间，使用年月选择并保存为 `YYYY-MM`。人才库的毕业时间自动取最高学历教育经历的毕业时间；仅校园招聘人才显示 `YYYY届`，社会招聘不计算应届届别。学历可选专科、本科、硕士、博士；招聘渠道可选校园线下、校园平台、智联招聘。联系方式支持手机号或带区号的固定电话。

校园招聘与社会招聘人才均可填写多条工作经历；每条包含工作单位、岗位、开始时间、结束时间和工作描述，其中工作单位必填、岗位可选填，结束时间留空表示至今。工作经历使用独立子表和独立前端组件，切换招聘类型不会删除已有经历。Excel导入导出暂不包含多条工作经历，需在人才库编辑页维护。

社会招聘人才还可填写多条项目经历；每条包含项目名称、担任角色、开始时间、结束时间和项目描述，其中项目名称及开始时间必填、担任角色可选填，结束时间留空表示至今。项目经历使用独立子表和独立前端组件，仅社会招聘人才显示；切换为校园招聘并保存时自动删除已有项目经历。Excel导入导出暂不包含多条项目经历。

简历支持PDF、DOC、DOCX，每份最大50MB；管理端及学生登记页面均可上传。文件与档案在同一数据库事务中保存，提交失败不会留下附件；下载须管理员登录。编辑时可保留、替换或移除附件。删除人才档案时，未被其他记录引用的普通附件会被清理；简历收集中的原附件继续保留，关联简历恢复为待识别，可以重新识别录入。与面试等业务记录关联的档案仍无法直接删除。数据库备份包含附件。

Excel模板只包含可填写的业务字段，不包含创建日期、年龄、毕业届别或附件。导出包含自动计算结果及简历文件名，不将简历文件嵌入工作簿。导入后需在档案编辑页补充简历。旧版人才数据首次升级时会自动生成 `before-candidate-update-*.db` 备份，保留原创建时间和关联编号，将“大专”归一为“专科”，毕业日期保留到年月；旧学历原值存于 `legacy_education`。旧版招聘阶段等附加字段保留在数据库，新表单按当前字段清单展示。

### 完整应聘登记

学生页面 `/apply` 同步应聘登记所有可见字段，排除初筛情况、是否需要一面、数据状态、是否名校优生。保持联系电话、姓名、身份证优先填写，支持身份证校验、年龄/届别计算、成绩单/证书/简历上传和手写签名。为建立人才档案，电话、专业、学历沿用学生页必填规则。提交会在同一事务内生成完整应聘登记和人才基础档案；数据状态由服务器固定为已生效，其他三个内部字段固定为未填写，学生请求无法自行设置。创建日期同样不可指定。学生页面不提供未经登录的按手机号查询人才资料，也不能读取附件。相同电话重复提交仍会被拦截，修改资料需联系招聘工作人员。

应聘登记弹窗按联系电话、姓名、身份证的顺序优先填写，列表字段顺序保持不变。填写18位身份证后自动从第7至14位提取出生日期、按第17位奇偶填写男/女，并计算周岁；小写x统一转大写X。出生日期及性别在身份证完整时自动填写并锁定，清空身份证后可手动填写。保存和Excel导入在服务端再次计算，避免客户端提交的值与证件号码冲突。校验包含18位格式、出生日期、非零顺序码及MOD 11-2校验码；填写、保存、Excel导入均执行校验，错误时阻止提交。通过校验不代表已联网核验身份或证件真实性。编码规则参考[居民身份证查验核查要领](https://www.spt.gov.cn/xxgk/zfxxgkml/201911/t20191108_1842403.html)。

应聘登记按基本信息、教育与语言能力、补充资料、招聘信息分区，包含姓名、毕业院校、初筛情况、一面需求、专业、性别、民族、籍贯、出生日期、电话、邮箱、学历、入学形式、学位、成绩单、语言能力、英语能力、其他语言能力、证书、年龄、签名、专业类别、简历、其他专业、创建日期、数据状态、政治面貌、身份证、健康情况、雅思/托福成绩、岗位、毕业届别、日期、简历渠道及985/211/双一流/名校优生标记。入学时间和毕业时间仅在教育经历子表中维护。

初筛为合格/不合格，一面需求及各院校标记为是/否；学历与人才库相同。入学形式为普通全日制、非全日制、统招专升本；语言能力为英语、其他、无；英语能力按业务清单配置为 CET-4、CET-5、无。简历渠道为校园线下、校园平台、智联招聘。数据状态仅为草稿、已生效；管理端新增及Excel缺省状态为草稿，学生正式提交后为已生效。旧版待处理/空状态转为草稿，已筛选/已安排面试/已结束转为已生效，原值保留在legacy_data_status中。未填写的标记保持为空，不自动判断。身份证作为文本保存。

应聘登记不再展示“关联人才档案”栏位，填写联系电话后自动按相同号码查询人才库并带入姓名、院校、专业、学历等资料；未匹配时可独立填写。姓名、毕业院校必填。Excel导入也可按联系电话匹配，系统内部保留关联编号用于数据一致性。带入资料作为本次登记快照保存；普通字段修改不反向修改人才库，但关联登记保存的教育经历会同步到人才库。通过匹配人才的院校档案带入985/211/双一流标记，无唯一匹配时不推断。新建登记或变更电话后，保存时复用匹配人才的简历（可上传替换）；电话改为未匹配人员时清除原人才简历及教育经历关联。每条教育经历的入学年月不能晚于毕业年月；年龄和届别自动计算，创建日期保留首次提交时间且不可修改。学生简版登记会自动生成带基本资料的应聘记录，其他资料可在管理端补充。

成绩单、证书支持PDF、DOC、DOCX、JPG、PNG；简历支持PDF、DOC、DOCX；签名可上传JPG/PNG或直接手写。每个附件字段一份文件，每份最大50MB。新建关联登记时可复用人才简历；替换或删除某个记录的附件不会影响其他记录仍在使用的附件。所有附件下载均要求管理端登录。Excel导入只处理文字和日期，附件另行上传；导出显示各附件文件名，保留所有表单字段。

旧版应聘登记首次升级时自动备份为 `before-application-update-*.db`，保留原编号和创建时间，从关联人才补齐基础资料。校园宣讲会/校园双选会归入校园线下，学生自主登记归入校园平台，原渠道保留于 `legacy_channel`；无法对应的新字段留空待补充。

### 面试情况表

面试表包含姓名、专业、毕业院校、性别、籍贯、出生日期、年龄、联系电话、是否一面、流程状态、学历、成绩单、证书附件、岗位、简历、创建日期、政治面貌、身份证、语言能力、面试时间、是否名校优生、性格、家庭情况、在校职务、专业实习情况、可接受项目地及其他项目地、是否通过一面、一面/二面情况说明、面试结果、个人意向和基本情况。入学时间和毕业时间仅在教育经历子表中维护；列表展示全部业务字段，不显示编号。

是否一面为同意/拒绝/不合适；流程状态为草稿/已生效/进行中/已取消，默认草稿；面试结果严格采用 `pass`、`发offer`。是否通过一面、专业实习情况、名校优生使用是/否。面试时间保存、显示及Excel导出精确到分钟，额外秒数会去除；创建日期仍精确到秒并不可修改。身份证验证和年龄计算沿用应聘登记规则。

面试表填写有效身份证后，按同一身份证号从应聘登记中带入资料，不再按手机号调取人才库；不区分末位X的大小写。相同身份证有多份登记时采用编号最新的一份，即使该应聘登记未关联人才也可匹配。未匹配时可手动填写姓名和毕业院校。成绩单、证书、简历在新建或变更身份证后保存时从匹配登记复用，也可自行上传，每份最大50MB；删除面试记录不影响其他记录仍使用的附件。Excel导入同样按身份证匹配。面试状态、结果和说明单独维护，不会反向改写人才库或应聘登记。应聘登记本身仍保留原有按手机号带入人才库资料的功能。

旧版首次升级会生成 `before-interview-update-*.db` 备份，保留原编号、创建时间、面试官、轮次、日期、评分和记录。原待面试/空状态转草稿，其他旧结论转已生效，原值存于 `legacy_status`；旧结论不自动推断为 `pass` 或 `发offer`。仅有旧面试日期时不猜测小时分钟，新的面试时间留空待补充。

系统采用“公共核心 + 独立功能模块”结构。每个功能的字段定义、后端专用规则和前端专用交互分别放在 `features/<功能名>/` 与 `web/features/<功能名>.js`。完整目录、修改入口、停用方法和依赖关系见 [功能模块说明](功能模块说明.md)。

已建库后新增字段仍需配合数据库迁移，不能仅修改模块内的 `schema.json`。

### 管理员任命

固定账号 `admin` 可通过“头像 → 查看成员”任命成员为管理员、取消其管理员权限或直接重置成员密码。重置时无需成员原密码，保存后该成员的现有登录会话立即失效。被任命的管理员可以创建、查看、注销成员账号，并拥有全部业务数据操作权限，但不能任命管理员、取消管理员或重置成员密码。创建账号接口始终创建普通成员，角色调整只能由 `admin` 单独执行。身份与权限保存于数据库，接口在每次请求时读取当前权限；刷新页面可更新菜单显示。
